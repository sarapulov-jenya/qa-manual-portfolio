# Ручное тестирование веб-приложения «Яндекс.Самокат»

*Manual testing portfolio: Yandex Practicum diploma — checklist, validation (equivalence classes & boundary values), test cases and 57 bug reports for the «Yandex.Scooter» web app.*

Дипломный проект по ручному тестированию: проверил веб-сервис аренды самокатов по требованиям, составил тестовую документацию и оформил найденные дефекты в баг-репорты. Всё лежит в одном файле: (yandex-scooter-manual-testing.xlsx).

[Смотреть в Google Таблицах](https://docs.google.com/spreadsheets/d/1yVvxut_a4Z474dYXLj-8wcUFptwrcFU94fU-KqXa8d8/edit?usp=sharing)

## Что тестировалось

- **Объект:** веб-приложение «Яндекс.Самокат», учебный стенд https://qa-scooter.praktikum-services.ru/
- **Основа для тестов:** требования к веб-приложению (лендинг, форма заказа «Для кого самокат» / «Про аренду», экран «Статус заказа», отмена заказа)
- **Охват:**
  - экран «Статус заказа»: поиск заказа из шапки, карточка заказа, отмена заказа, экран ошибки, все 5 статусов заказа;
  - валидация 9 полей формы заказа;
  - интерфейс формы заказа (баги вне тестовой документации);
  - отмена заказа через API (`PUT /api/v1/orders/cancel`);
  - тест-кейсы для курьерского Android-приложения: пуш-уведомление о сроке доставки и отсутствие интернета.

## Техники и подходы

- **Классы эквивалентности и граничные значения:** для каждого поля формы выделены валидные и невалидные классы, проверены значения на границах (например, длина имени 1/2/3 и 14/15/16 символов, телефон 10/11/12 цифр).
- **Граничные значения во времени:** пуш-уведомление проверено в 21:58, 21:59 и 22:00.
- **Тестирование переходов между статусами:** проверено, какой статус заказа становится активным после действий курьера в приложении.
- **Кросс-браузерное тестирование** в двух браузерах и двух разрешениях.
- **Подмена ответа сервера через DevTools (Overrides):** так проверен статус «Время аренды кончилось», который нельзя вызвать обычным путём.
- **Анализ требований:** найдено противоречие в требованиях к полю «Имя» (тире вместо дефиса), на него заведён отдельный баг-репорт.

## Результаты

**Чек-лист (241 проверка × 2 браузера):**
- 206 проверок пройдены в обоих браузерах;
- 34 не пройдены: 31 в обоих браузерах и 2 только в Яндекс.Браузере 1920×1080;
- 1 заблокирована другим багом.

**Валидация (70 классов):** 56 пройдены, 14 не пройдены, одинаково в обоих браузерах.

**Баг-репорты: 57**

| BUG: экран «Статус заказа» и отмена заказа | 31 |
| V-BUG: валидация формы заказа | 16 |
| NTD: вне тестовой документации | 10 |

По приоритету: 1 блокирующий, 11 критических, 26 стандартных, 19 желательных.

**Примеры найденных багов:**
- `BUG-18` *(критический)*: отменённый заказ по-прежнему доступен для просмотра.
- `BUG-13` *(критический)*: в графе «Когда привезём» к дате доставки прибавляется срок аренды.
- `BUG-10` *(критический)*: пользователь выбрал станцию «Сокольники», а в заказе указана «Красносельская».
- `V-BUG-4` *(критический)*: поле «Адрес» можно оставить пустым и перейти к следующему шагу.
- `BUG-30` *(критический)*: заказ не отменяется запросом `PUT /api/v1/orders/cancel`, сервер отвечает 400.
